# Common SE Tools & Techniques

> Domain: SE Foundations · Learning order: 4 · Bloom target: Understand

## Overview

This topic is the **catalogue of the instruments a systems engineer reaches for**: the software tools (requirement managers, MBSE modellers) and the disciplined techniques (trade-off analysis, risk management, V&V, interface management) that keep a complex system aligned with stakeholder needs across its lifecycle (source: m1-tools). It also introduces the **ISO/IEC/IEEE 29148** family of five requirements documents that gives those tools a standard structure (source: m1-tools). This is an *introductory map* — it names each tool/technique and gives a one-paragraph definition; the deep mechanics live in their home topics. So: tools and high-level technique definitions **here**, vs. the detailed *how-to* of SysML in topic 08, requirements management in topic 07, trade-offs in topic 12, V&V in topic 16, and ICDs in topic 14.

**What you already know that connects here:** [01-se-fundamentals](../01-se-fundamentals/README.md) gave you the idea that SE manages complexity and stakeholder needs holistically; this topic hands you the concrete tools and techniques that do that work.

## Learning objectives

After this topic you will be able to:

- (Understand) Classify a named tool as a requirement-management tool, an MBSE tool, or a technique.
- (Understand) Explain the purpose and result of each of the five ISO/IEC/IEEE 29148 documents (BRS, StRS, SyRS, SRS, OpsCon).
- (Understand) Describe what trade-off analysis, risk management, V&V, and interface management each contribute, using the communications-satellite antenna example.
- (Understand) Distinguish verification from validation and FMEA from FTA.
- (Apply) Map appropriate tools/techniques to the lifecycle stages of a chosen system.
