# System Lifecycle Models

> Domain: SE Foundations · Learning order: 3 · Bloom target: Apply

## Overview

A **system lifecycle model** is the chosen way to *sequence and iterate* the engineering work — linear and front-loaded (Waterfall), test-paired (V-Model), risk-driven cycles (Spiral), or short adaptive sprints (Agile). There is no single best model; each suits a different kind of project (source: m1-lifecycle). Contrast this with **[02-se-process-stages](../02-se-process-stages/README.md)**: the *stages* are the phases a system passes through (concept, design, build, test, operate); the *models here* decide how you order, repeat, and overlap the work that moves a system through those stages.

**What you already know that connects here:** [01-se-fundamentals](../01-se-fundamentals/README.md) frames systems engineering as a disciplined, whole-system approach — lifecycle models are the concrete scheduling shapes that discipline takes.

## Learning objectives

After this topic you will be able to:

- (Apply) Walk a concrete system (e.g. a smart door lock) through each phase of a chosen lifecycle model and name the artifact each phase produces.
- (Apply) Select a lifecycle model for a given project and justify the choice from its requirements stability, risk profile, and feedback needs.
- (Understand) Explain how the V-Model pairs each design phase with a corresponding test phase.
- (Understand) State the four Agile Manifesto values and what each one favours over.
- (Analyze) Contrast Waterfall, V-Model, Spiral, and Agile for the same scenario and diagnose which fits best.
