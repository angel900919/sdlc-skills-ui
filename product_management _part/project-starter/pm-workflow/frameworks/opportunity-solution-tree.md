# Opportunity Solution Tree (OST)

A visual map that connects a desired **outcome → opportunities** (unmet needs / pains) **→ solutions → experiments**, so the path from problem to bet is visible, comparable, and defensible. Primary source: **Teresa Torres (Product Talk)**. (Canon: [`05_Conventions.md` §8](../05_Conventions.md); phase map: [`03_Frameworks_Map.md`](../03_Frameworks_Map.md).)

## What it's for / when to use
- Making discovery-to-delivery decisions visible and traceable to *one* outcome.
- Comparing 2-3 opportunities and 2-3 solutions instead of committing to the first idea.
- A living weekly layer that pairs with Continuous Discovery.

## The steps
1. Put one clear, measurable **outcome** at the root.
2. Branch the **opportunity space** — distinct customer needs / pains / desires drawn from interviews (not solutions).
3. Pick a **target opportunity** (assess reach, importance, strategic fit).
4. Branch 2-3 **solutions** under that opportunity.
5. Branch **experiments / assumption tests** under each solution; test the *riskiest* assumption first.
6. Update the tree continuously as evidence arrives.

## Worked micro-example
Outcome: "Increase weekly active teams by 15%." Opportunities (from interviews): (a) "new members don't know where to start," (b) "admins can't tell who's stuck." Target (a). Solutions: a guided setup checklist vs. a sample-project template. Experiment: prototype the checklist with 5 new teams and measure day-7 return → then decide.

## When NOT to use it
- Pure delivery / execution sequencing — use a backlog, story map, or WSJF; the OST is a discovery artifact.
- When there's only one possible way to address the need — that's a solution masquerading as an opportunity; no tree needed.
- As a static, one-time diagram — a "frozen tree" defeats the purpose.

## Common mistakes / anti-patterns
- Solutions disguised as opportunities in the opportunity space.
- Jumping straight to one solution with no alternatives compared.
- Treating the tree as a one-time deliverable instead of a living layer.
- Opportunities not tied to a single measurable outcome (or tied to a vanity outcome).
- Skipping the experiment layer — opinion-driven / HiPPO selection instead of assumption tests.
